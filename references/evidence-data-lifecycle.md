# 证据数据生命周期与不可变性合同

普通页面工具响应先经 `source_capture.py` 自动登记，再进入既有采集链；`capture --tool-result` 可在一次调用内完成。登记只绑定本次实际工具输出，不导入任意项目文档；登记、原始内容、工具身份与当前查询执行在后续复验中必须一致。详细字段及逐区块可见性见 `host-page-receipts.md`，不另建正式来源或评分体系。

## 1. 单向数据链

所有 URL 处理遵守 `url-contract.md`。原始事实、传输节点、最终页面及公开隐私副本分离；业务查询以可逆字节片段保留。旧身份规则变更只可显式重建独立候选包，原件、旧运行和旧封印不得原地改写或冒充当前正式真值。

来源采集以前先完成机器查询计划事务，并从真实检索观察生成已绑定执行记录；字段与命令见 `execution-facts.md`。`source-capture-record-template.json` 中的执行身份与哈希从对应正式执行逐项复制，准入器只能传导，不能重新推测查询、轮次或时间。来源、执行、计划任一链条断裂都会阻断后续正式审计；相同页面由不同查询发现时保留各自追加关系，而页面实体仍按既有规则去重。

正式研究只允许以下单向链：

```text
公开页面实际读取
→ Tool Trace / Optional Host Receipt Verification（工具读取溯源与可选宿主收据核验）
→ Source Capture（来源采集）
→ Candidate Staging（候选暂存）
→ Pre-admission Audit（准入前审计）
→ Atomic Promotion（批次原子提升）
→ Canonical Formal Evidence（正式不可变证据）
→ Derived Analysis（派生分析）
→ Run-level Truth Freeze（运行级真值冻结）
→ Report Truth（机器报告事实）+ Narrative（定性叙事）
→ Office → Read-only Validation（只读验收）
```

任何下游派生结果均不得反向修改上游事实。执行 Agent 可以继续检索、修改候选判断或重建派生物，但不能通过改写正式原文、来源、定位、主维度、语义分、审计状态或评分来满足门槛。

## 2. 六个逻辑目录

任务工作目录使用 `capture/`、`staging/`、`canonical/`、`derived/`、`audit/`、`artifacts/` 六层。资产 `run-directory-layout.json` 给出机器可读建议。新生成的状态、清单和冻结引用统一保存运行根目录相对逻辑路径、工件角色和内容哈希；绝对路径只允许作为旧运行迁移时的兼容输入，不进入新工件哈希。整个运行目录移动到其他磁盘、含中文或空格的目录后，应从当前状态文件位置重新绑定并保持审计结果不变。不同真值层不得写入同一个可覆盖文件。

- `capture/`：追加式采集清单、内容寻址快照、正文块索引；
- `staging/`：可编辑候选来源、候选证据、待编码队列、叙事输入；
- `canonical/`：不可变正式来源、不可变正式原始证据、追加式纠错事件、机器物化的 active 视图；
- `derived/`：语义证据、正式计分证据、平台与综合评分、机器报告事实、叙事登记版、报告数据；
- `audit/`：准入、定位、碰撞、证据充分性、真值冻结、预报告预检、最终错误清单；
- `artifacts/`：四份正式交付物。

## 3. 来源采集层

采集先按 `host-page-receipts.md` 核验本次实际工具记录与原始结果，普通路径为 `tool_traceable`，不要求签章和 IP；真实签章存在时保留 `host_verified` 增强验证。保存证明等级、原始结果哈希、派生的 `network_observation`、`platform_mapping_sha256` 和 `final_url`，传导至正式来源。无工具读取依据的自报内容只能留候选层。原始/候选发布日期须受本次采集日、检索日和保护的研究截止日约束，未来活动时间另列，未知发布日期保留为空。

原始响应在快照目录的 `.private-response/` 中限制操作系统权限，按内容寻址不可覆盖，不进入普通交付；写入采用同目录事务临时文件、跨进程锁、刷新与 `fsync`、大小和 SHA-256 复验及原子改名。事务日志记录目标、临时文件、预期哈希、大小、阶段与所有权；中断恢复只处理所属临时文件，保留哈希一致的共享成品，对未知冲突失败封闭并支持幂等重试。正文由发布版算法提取并等长遮蔽明确联系方式，分别记录原始响应、提取原文、脱敏正文、处理规则与字符偏移映射哈希。URL 内数字依参数名和路径语境区分内容编号、明确联系方式与歧义项；歧义不冒充确认泄露，也不改写签名 URL。标题与摘要同样脱敏，历史导入和恢复不得豁免。去重比较不将脱敏占位符制造的公共尾部当作复制证据，实际存储文本、定位和精确内容复验保持不变。

`source_capture.py` 每次记录工具实际读取到的内容。脚本统一完成 URL 规范化、最终跳转 URL、域名和稳定 `platform_id` 派生、页面实体标识、快照 SHA-256、正文块范围、事件哈希链与同 URL 版本递增。采集清单与快照都不可覆盖；再次访问必须产生新 capture 事件。并发进程写同一清单时，编号分配、前序哈希读取、事件哈希计算、追加写入和 `fsync` 必须位于同一跨进程临界区，不以随机等待掩盖竞争。进程异常后只能显式检测并恢复截断尾行；完整历史行不得丢弃或重排。

可读正文只允许 `full` 或 `partial`。摘要、元数据、受限和不可访问状态不能声称存在正文。结构化原生评分可在 `metadata_only` 或可读页面下保存为 `native_numeric_observation`，其数值、量表上下界、评价对象、平台、页面实体、采集时间、可复验来源和快照同样写入内容寻址记录；该专用路径不得生成虚假正文或摘要原文。

采集层只回答“本次工具实际看到了什么”，不回答来源是否相关、证据属于哪个维度、情感为何、是否评分。

正文格式、依据和可见性等级由同一次原始结果处理派生：`body_format / body_provenance / visibility_proof_level` 随采集传至正式来源，正文块继承等级。HTML 静态抽取结果不是浏览器渲染声明，`unconfirmed` 用户块不能晋升为用户证据；保留候选或非用户背景并按真实工具重读，新采集另建事件。纯文本工具结果保持普通路径，所有等级继续受原始结果、块、定位和规则哈希复验。

## 4. 候选暂存层

候选来源和候选证据可被删除、拆分、合并、重新分类和重新编码，但始终保留 `candidate_* → capture_id`。候选数据不是正式页面或正式证据，不参加 150 页、历史兼容警戒值 100、所选置信目标理论总量及逐维 25/40/60 统计。

模型生成的解释只能写 `researcher_summary` 等解释字段。`original_visible_text` 必须来自对应快照；不得为了词表命中、情感方向或报告文字补写任何短语。

## 5. 准入前审计与批次提交

`pre_admission_audit.py` 是新增 canonical 来源和证据的唯一正式接口。批次在首次正式写入之前完成：

1. task、capture、快照和事件链核验；
2. URL、最终跳转、`platform_id`、页面实体、采集层权威来源类型、内容层级与直接地点关系核验；
3. 文本在快照中的定位、字符起止、正文块、文本及 locator 哈希核验；
4. 原生数值与其捕获快照核验；
5. `unit_type` 与 `content_layer` 一致性；
6. 唯一 `primary_dimension`；
7. 同批、既有正式记录、URL 与文本碰撞检查；
8. 正式 ID、promotion audit 与 immutable input snapshots（不可变输入快照）生成。

所有检查通过后才写正式路径，准入审计提交文件最后落盘。任一记录失败时不得产生合法提交。若进程异常导致多个文件之间存在部分替换，后续 `verify_admission_commit` 会因输出哈希不匹配硬失败，不能把半写入状态当作正式数据。

## 6. 定位与原生数值

文本证据必须拥有 snapshot-local locator（快照内定位），至少包含 capture、snapshot hash、字符起止、正文块及 locator hash。空 locator、超界 offset、文本与快照不一致、hash 不一致均拒绝准入。

正文块合同由 `content_blocks.py` 唯一定义：`is_user_generated` 只接受 JSON 布尔值，偏移只接受非布尔整数，块编号唯一，禁止重叠和父子块同时作为可评分块。块类型与用户属性遵守唯一矩阵：官方事实、新闻、学术和元数据块必须为非用户内容，帖子、评价、评论和回复块必须为用户内容，`page_body` 仅作上下文类型；冲突在采集、准入、核心审计、正式资格和最终验收均失败。证据必须恰落在一个语义一致的叶子块，且文本、块哈希、正文哈希和识别规则哈希全部一致；调整块顺序不能改变结果。规则文件变更使旧识别哈希失效，不能沿用缓存资格。同一机构页面可以同时包含背景事实与真实用户评论，但二者须分别定位为独立叶块，只有后者进入正式用户证据判断。原生数值三个字段使用共享有限数解析，不接受布尔、空值、NaN、Infinity、越界或非递增量表；结构化工具原始结果（或可选签章响应）必须包含并绑定这些数值，不能从纯文本响应外部补填。

`source_native_numeric` 不伪造文本定位。它只接受采集事件保存的原生数值、最小值、最大值、评价对象、平台、页面实体、采集时间、可复验来源和快照；candidate 只能复述相同字段，不能更改。已有确定性方面归属能够唯一识别维度时自动写入唯一 `primary_dimension`；仍不确定时进入正式维度复核，而不是因无正文拒绝或伪造文本。任何必需元数据不完整时拒绝该路径。该路径只复用既有原生数值换算，不改变评价协议。

## 7. 内容类型与平台血缘

平台显示值和缓存与机器派生值必须一致；来源与证据填入同一个虚构名称也不能获得正式资格。核心审计、维度覆盖、正式评分入口和最终验收重做公开身份、平台映射哈希和时间资格检查；非法记录不贡献计数或穷尽依据。

正式 `platform_id` 始终由规范化 URL、最终跳转和受控主机映射机器派生；`www`、移动版、默认端口、默认首页、片段、跟踪参数和查询参数顺序统一处理，业务参数与路径参数继续保留。该页面等价身份只用于去重和平台映射。宿主收据另以严格传输身份逐跳绑定请求与最终 URL，完整保留路径参数、查询顺序、重复键和编码；两类身份不可互换。未知服务子域不会仅因注册域相同而自动合并。candidate 中的 platform 声明不能覆盖机器值；evidence 中的 platform 只是来源值的显示缓存，平台×维度评分统一读取 `platform_id`。

采集层 `source_type` 是正式来源分类的权威值。candidate 的 `source_category` 只作暂存输入：与采集值冲突时恢复采集值并留下机器审计记录，非法或无法映射的值拒绝准入，不得由候选分类改变来源结构统计。

`user_post`、`user_review`、`comment`、`reply` 必须定位于相同类型或明确标记为用户生成的正文块。普通 `page_body` 没有用户块证明时不得转成用户评价。官方事实与研究背景可以形成定性证据，但不能成为公众体验评分样本。

## 8. 跨来源文本碰撞

准入器检查规范化文本完全一致、高相似文本及三条以上重复模板尾句，形成稳定 collision group（碰撞组）和方法；完全一致只归入精确匹配，不再同时重复登记为高相似。短文本与长文本使用同一规范化和阈值边界。状态为：

- `unique`：未发现碰撞；
- `verified_independent_occurrence`：来自不同机器页面实体、各自在正式快照中可定位，且通过受信任签章的独立出现复核；
- `repost`：转载；
- `mirror`：镜像；
- `duplicated_extraction`：同来源重复提取；
- `unresolved_collision`：当前无法证明独立性。

候选记录自行声明独立出现无效，也不能提供可信复核签章。除前两类外均不计分；即使来源编号不同，同一页面实体也不能形成多个独立出现。后续新批次发现旧记录碰撞时，不改写 canonical；机器重建 active view，并在当前派生视图中排除未解决组。

碰撞复核与语义复核共用发布前 `review-trust.json` 的身份/权限校验。`collision_review_proof` 保存公开可验证的决定及集合绑定，canonical、当前视图、碰撞审计、页面独立出现统计和最终验收复用同一证明；旧布尔标记或普通本地密钥不能替代。既有已签决定只在相同任务及完全匹配的碰撞集合内复用，不向新增成员扩展权限。秘密密钥不写入这些工件。

## 8.1 页面实体

正式页面数量按页面实体计算，不按 `source_id` 计算。页面实体由统一规范 URL、经核验的最终跳转 URL、内容指纹和碰撞关系确定性合并；同一页面的参数变体、镜像和不同 URL 下的相同内容不增加数量。只有不同页面实体且具有可信独立出现复核的内容碰撞才可分别计数。审计输出必须保留每个页面实体的成员来源和合并理由。

## 9. 正式不可变与纠错

canonical 记录包含稳定 ID、capture/source/query 血缘、原文或原生值、快照 hash、locator、主维度、单元类型、promotion 批次与单条记录 hash。写入后禁止 UPDATE、DELETE 或覆盖。

合法纠错只允许 `canonical_correction.py` 追加：

- `retract`：撤销错误记录；
- `supersede`：由已存在的新正式记录替代旧记录。

纠错事件形成哈希链，已纠错记录不能重新启用。active 来源与证据是 canonical + correction + 当前 collision 的确定性派生视图，不是第二套事实台账。

## 10. 派生层与两级冻结

语义、人工复核、置信度、可靠性、评分资格、平台门禁、七维分、综合分和报告均在 derived 层重新生成。语义处理输入为 active raw evidence（当前有效原始证据），输出到新文件；不得原地修改 canonical。

Record-level immutability（记录级不可变）从每批提升时开始；Run-level Truth Freeze（运行级真值冻结）在证据审计允许评分后冻结整个正式集合。二者同时生效：前者阻止单条篡改，后者阻止进入评分和报告后更换整批输入。

## 11. 报告唯一真值

`compile_report_truth.py` 从冻结来源、证据、检索日志、审计、平台输入、综合评分、协议和代码簿自动生成 `report_truth.json`。语言模型不得填写其中任何数量、比例、分数、权重、轮次、协议或固定结果层字段。

模型只产生 `report_narrative.json` 允许的定性字段。`assemble_report_data.py` lint 后合并机器事实与固定模板；最多两轮叙事、两次报告数据提升。`report_truth_sha256`、`report_narrative_sha256` 与 `report_data_sha256` 共同绑定 Office 输入。

## 12. 两类验收语义

- `internal_consistency_validated`：正式台账、评分、报告及 Office 数值可相互复算；
- `source_grounded_evidence_validated`：active 证据原文或原生值可从当前 capture、snapshot 和 locator 独立复验。

两者均为 true 才能声明正式研究证据链通过。内部数值一致不能替代来源落地验证。
