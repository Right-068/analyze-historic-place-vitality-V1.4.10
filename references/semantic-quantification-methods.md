# 非结构化文字语义量化方法库

## 1. 目标与证据边界

本方法库用于处理没有原生星级、量表值或其他结构化数值，但包含可见评价语义的公开网络文字。目标不是把主观表达变成“客观事实”，而是把研究者原本隐含的判断拆成可复核字段：分析单位、主题、七维归属、情感方向、强度、上下文修正、语义置信度、证据可靠性、复核状态和计算轨迹。

必须同时遵守以下边界：

1. 原生数值与语义推断分开。页面明确显示的星级或量表值写入 `native_rating_*` 字段；文字推断写入 `semantic_*` 字段。不得用语义分值冒充来源原生评分，也不得让原生总评分自动替代七维文字编码。
2. 事实与态度分开。纯地点介绍、开放时间、地址、名录身份、规划表述和新闻事实可以进入背景证据，但没有评价立场时不得强行编码为中性满意度。
3. 缺失与中性分开。找不到方向性线索不能直接解释为中性；先标记词表缺口并启动编码解析，候选确认前保持 `sentiment=na`、`semantic_review_status=review_required` 和 `formal_scoring_eligible=false`。`used_for_scoring` 仅表示上游研究选择意图，不能绕过正式资格。只有明确无倾向表达，或正负贡献落入中性带时才记 `neutral`。
4. 推断与复核分开。规则或语义相似度只能生成候选编码；低置信、冲突、反讽、指代不清和维度并列必须进入复核队列。
5. 语义强度、证据可靠性和汇总权重分开。强烈措辞不代表证据更可靠；高可靠来源也不能把负面评价“校正”为正面。
6. 所有判定仅使用当前 `task_run_id` 中实际读取的文字。方法、代码和空白代码簿可以复用，既往样本、词频、主题和结论不得带入新任务。

## 2. 方法库总览与选择规则

| 方法族 | 主要输入 | 主要输出 | 适用位置 | 不可单独承担的任务 |
|---|---|---|---|---|
| 内容分析与分析单位切分 | 可见正文、评论或帖子 | 最小可解释语义单位 | 全流程入口 | 不能直接产生满意度 |
| 代码簿型主题分析 | 语义单位、七维定义、开放编码 | 规范化主题、主维度、次维度 | 主题编码与七维归属 | 不能证明主题频率代表总体人口 |
| 方面级情感分析 | 主题或方面与局部评价语句 | “维度—倾向”成对结果 | 同句多方面、七维评分 | 不能把整段总体情感平移给所有维度 |
| 词典与规则组合 | 极性词、否定、程度、转折、弱化、标点 | 可解释的连续倾向分 | 中文短评和可审计基线 | 不能可靠解决所有反讽、隐喻和语境依赖 |
| 语义相似度 | 语义单位、维度定义与主题原型 | 维度候选及相似度 | 词面不重合、同义表达 | 不能把高相似度当作真实倾向 |
| 主题模型或聚类 | 规模足够且同质的语料 | 候选主题簇 | 发现代码簿遗漏 | 不能自动给主题命名或判断正负 |
| 比较式强度标注 | 可比较的同类语义单位 | 相对强度排序 | 词典校准、边界样本复核 | 不能替代维度识别与证据审计 |
| 监督或辅助语义判定 | 已审定代码簿、结构化输出约束 | 候选维度、倾向、理由、置信度 | 平台具备语义能力时的第二路径 | 不能以黑箱结论直接入分 |
| 编码一致性检验 | 两名或多名独立编码者的结果 | 一致性系数、分歧清单 | 代码簿试编码和正式抽检 | 不能用一致性替代编码有效性 |

默认组合不是“选择一个最先进方法”，而是：读取发布锁定协议 → 核对版本与 SHA-256 → 双语词项与近义释义检索 → 分析单位切分 → 七维候选 → 方面级极性 → 规则修正 → 零命中编码解析 → 置信度 → 复核 → 一致性 → 聚合。语义相似度、主题模型和辅助语义判定仅作为补充路径；单次地点任务不得在线修改评价协议。

## 3. 强制执行流程

### 3.1 发布校准与任务期锁定

语义规则的在线更新只在修订并发布 Skill 版本时执行，不属于单次地点研究。发布维护者使用 `assets/evaluation-protocol-calibration.json` 记录不少于三条实际方法查询、不少于三个可读方法来源、至少两个独立域名，以及 `retain`、`modify`、`add` 或 `deprecate` 决策；优先使用一手论文、官方项目或正式技术文档。

发布流程固定为：在线核验 → 适用性与证据边界审查 → 修改候选 → 人工评审 → 回归与基准测试 → 生成锁定代码簿 → 计算 SHA-256 → 发布。只有 `regression_status=passed` 和 `benchmark_status=passed` 才能生成正式规则工作簿。评分规则、权重、阈值、上下文作用域或代码簿实质变化必须更新评价协议或语义代码簿版本；仅报告模板和非评分实现变化可保持评价协议版本不变。

正式地点任务只读 `assets/evaluation-protocol.json` 与 `assets/semantic-quantification-codebook.json`，核对 `evaluation_protocol_version`、`semantic_codebook_version` 和 `semantic_codebook_sha256`。不得生成任务绑定代码簿，不得以“当前方法更先进”为由临时改变规则，也不得把任务中发现的新表达直接写回词表。

任务中词表部分命中或零命中时继续编码解析。候选表达、俚语、新用法或未知概念进入复核队列；只有在当前任务内完成结构约束辅助编码或人工裁决后才能用于该条证据，且仍不修改锁定协议。具有跨任务价值的候选另行进入未来版本发布校准清单。

### 3.2 资格判断

文字进入语义量化前必须同时满足：页面为 `full` 或 `partial`；文字在当前页面实际可见；与研究对象直接相关；不是搜索摘要、聚合数量、仅星级、纯转述或不可访问页面；不是疑似推广；完成证据层去重；保留 `original_summary_text`。

不满足资格的文字可以保留为事实或线索，但正式评分资格必须为否且不得进入平台计分。不得为了达到样本目标而降低此门槛，也不得用上游 `used_for_scoring` 意图字段代替资格判定。

### 3.3 分析单位切分

先按句号、问号、叹号、分号和换行切分，再检查逗号连接的并列对象、转折结构和指代关系。一个证据行应尽量只包含一个可独立解释的评价命题。若一句同时评价多个维度，可以保留同一 `evidence_id` 并记录主、次维度；若各分句方向相反且对象不同，应拆成带父级关系的独立证据单位，避免把总体净值错误归给两个维度。

以下内容不能作为独立用户样本拆分：平台自动摘要中的“部分用户认为”；同一评论的机械分句；一个页面显示的总评论数；复制转载；研究者对多条评论的综合转述。

### 3.4 主题编码与双语代码簿

采用“演绎代码簿 + 归纳补充”的混合流程：

1. 先用七维定义建立一级代码。
2. 在每个一级代码下，从当前样本提取具体问题或体验作为开放代码。
3. 合并同义、上下位和轻微改写，形成 `normalized_theme`。
4. 保留合并前线索、合并理由和代表性匿名摘录。
5. 新主题不能仅因出现一次就扩写成稳定模式；低频主题应标注为个案或待验证。

代码簿的每个核心概念至少包含：稳定 `concept_id` 或 `dimension_id`、中文词项、英文词项、中文近义释义、英文近义释义、中文定义、英文定义、极性或维度标签以及机器读取路径。中文与英文分栏存储；混合语言文本分别匹配后合并轨迹。近义释义参与检索，定义主要用于零命中后的概念画像比较，不能把整段定义当作无条件极性词。

英文词项使用不跨词边界的大小写不敏感匹配，并保留基础词形归一；中文使用最长优先、不重叠匹配。任何新增词项都必须说明语言、概念归属、近义边界和反例，避免把多义词机械赋为固定正负值。

主题频率使用去重后的有效证据单位计算。报告主题“常见”时必须给出分母、计数或提及等级；不得用搜索排序和页面热度替代提及率。

### 3.5 七维方面归属

七维名称、顺序、定义和边界以 `references/seven-plus-one-framework.md` 与 `scripts/dimension_framework.py` 为规范，种子线索由 `assets/semantic-quantification-codebook.json` 提供。结果层“历史文化活态传承感知评价”不参与单条证据的并列维度归属。归属顺序如下：

1. 文本明确指向某维度时，记录声明式候选。
2. 统计七维种子线索的命中与分布。
3. 若声明候选与词面候选一致，记录 `declared+lexical_agreement`。
4. 若不一致，记录 `declared_lexical_conflict`，不得自动覆盖。
5. 无声明候选但存在清晰词面优势时，记录 `lexical_candidate`。
6. 词面不足且运行环境具备句向量能力时，可计算文字与七维定义、已审定主题原型的余弦相似度；必须保存方法、阈值、前两名相似度及差值。
7. 仍无法区分时记录 `unresolved`，不得用任何七维或结果层充当残余文字的兜底类别。

一个单位最多设置一个主维度和一个确有证据的次维度。多标签统计时必须说明同一证据可贡献多个“提及”，但有效样本总数仍按去重证据单位计算。

### 3.6 极性与强度

词典与规则基线对每个极性线索计算局部贡献：

`局部贡献 = 极性方向 × 词典强度 × 否定因子 × 程度因子 × 转折位置因子 × 弱化因子 × 标点因子`

同一分析单位的局部贡献求和为 `raw`，再进行有界归一化：

`semantic_score_raw = 5 × raw / sqrt(raw² + 15)`

结果限制在 `[-5, +5]`，并按远离零的半入规则得到整数 `semantic_score_final`，以兼容七维量表。这里的常数和各修正系数是透明、可调整的操作参数，不是普适心理尺度；正式研究必须在方法章节披露，并对临界样本进行敏感性检查。

默认上下文规则：

- 否定只在同一分句、极性线索前六个字符内生效；奇数次否定反转，偶数次否定恢复。超出局部范围或存在复杂句法时进入复核。
- 程度副词只修正其后最近的极性线索；极强、增强、减弱系数从代码簿读取。
- 转折词前分句权重为 `0.75`，后分句权重为 `1.25`，用于表达后项通常承载主要结论的操作假设；复杂多重转折必须复核。
- 不确定和弱化表达默认乘 `0.75`，但只降低表达确定度，不自动改变正负方向。
- 最多三个叹号参与强度修正，避免标点堆叠无限放大。
- 同一单位的正、负绝对贡献均不少于 `1.0`，且较小一侧不少于较大一侧的 `35%` 时记 `mixed`；仍保留净分以表示混合意见的总体方向。
- 绝对归一化分小于 `0.5` 且存在有效线索时记 `neutral`；没有方向线索时记 `na`。
- 反讽、隐喻、引用他人观点、问句式讽刺或表情与文字冲突时，不自动反转极性，设置 `figurative_risk=true` 并强制复核。

不得把“人多”一律视为高活力或负面拥挤，必须结合具体评价对象和句内方向；不得把“商业”一律视为负面，必须区分业态丰富、消费便利与过度商业化；不得把“古”“旧”脱离语境直接编码为正面历史感或负面破败。

### 3.7 零命中与部分命中的编码解析

完成中文词项、英文词项和两种语言近义表达检索后，按维度和极性两层形成 `lexicon_match_status`：`full_match`、`dimension_only`、`polarity_only` 或 `zero_hit`。任一层缺失即启动编码解析；两层均未命中时必须启动，不能直接结束、判中性或填写零分。

内置解析基线执行：语言检测 → 英文词形归一与中文二至三字片段化 → 与七维及极性概念的双语词项、近义释义、定义画像比较 → 生成稳定候选排序 → 建立 `OPEN-*` 开放编码编号。相似度仅用于候选检索，不是概率：默认候选阈值、强候选阈值和每类最大候选数均从发布锁定代码簿读取。

解析结果分为 `candidate_generated` 与 `started_unresolved`，均使用 `semantic_method=coding_parse_fallback`、`semantic_review_status=review_required`、`formal_scoring_eligible=false`，并把候选、实际词元、阈值、匹配依据和下一动作写入机器轨迹。候选存在也不得自动给分；解析器不覆盖上游研究选择意图字段。

随后必须启动结构约束的辅助编码或人工开放编码：回看原文、来源上下文、七维定义、候选及反例，形成主/次维度、极性、强度、理由和置信度。确认后将方法改记 `assisted_semantic` 或 `manual_code`，填写 `coder_id` 与 `adjudication_status`，保留原词表缺口和解析轨迹。仍无法确认时保持未解并排除评分；不能用任何七维、结果层或中性值吸收残余文本。

### 3.8 原生数值转换

只有页面明确给出数值、量表上下界和数值含义时，才允许线性归一化：

`native_rating_normalized = -5 + 10 × (value - scale_min) / (scale_max - scale_min)`

必须保留原值和上下界。平台总星级、单条用户星级、专项分项和研究者语义分值不得混在同一列后直接求均值。原生数值可以作为交叉验证或平台层背景，但能否进入七维分数取决于它是否明确指向对应维度。

### 3.9 语义置信度

`semantic_confidence` 由四部分组成：极性线索覆盖 `35%`、维度清晰度 `30%`、文本完整性 `20%`、规则清晰度 `15%`。冲突、反讽、多重转折、无方向线索和维度未解会降低分值。

自动候选同时满足以下条件时记 `auto_eligible`：

- `semantic_confidence >= 0.72`；
- `aspect_confidence >= 0.60`；
- `evidence_reliability >= 0.55`；
- 存在可解释的方向和主维度；
- 无声明—词面冲突、反讽风险或无效来源问题。

任一条件不满足即记 `review_required`。人工复核必须留下 `coder_id`、`adjudication_status` 和必要说明；不能只把状态改成已确认而不处理冲突原因。

### 3.10 证据可靠性

`evidence_reliability` 独立计算：直接相关 `25%`、明确体验 `20%`、地点相关程度 `20%`、文本完整性 `20%`、时间完整性 `10%`、非推广来源 `5%`。该值评估证据能否稳定支撑解释，不评价用户观点“正确与否”。

`aggregation_weight = semantic_confidence × evidence_reliability` 仅用于同一平台、同一维度内的证据汇总。它不得用于扩大平台样本量，也不得替代平台等权规则。每条记录仍按一个去重有效样本计数。

### 3.11 平台内与跨平台汇总

平台内、维度内先按去重证据单位计算加权平均语义分，再按远离零的半入规则转换为 `-5` 至 `+5` 整数倾向。一个平台在某维度少于三条合格证据时，该维度记缺失，不用 `0` 或 `50` 补位。

跨平台仍执行既有规则：先计算平台内七维结果，再做平台等权；只有平台样本计数可比且准确时才提供样本加权敏感性结果。语义权重只在平台内消化文字判定不确定性，不能使大平台再次获得跨平台双重权重。

### 3.12 编码一致性

正式使用代码簿前，至少对一批同时包含正面、负面、中性、混合、否定、转折、弱化和多维表达的样本进行独立双编码。两名编码者的名义分类报告 Cohen κ；两名以上、存在缺失值或需要不同测量尺度时报告 Krippendorff α。强度等级使用顺序距离，维度和情感使用名义距离。

一致性系数不是自动通过标准。建议把 `0.80` 作为可重复性良好的目标，把 `0.67–0.80` 视为可在明确限制下继续并加强复核的区间；低于此区间应修订定义、边界样例和冲突处理后重编码。无论系数高低，都要保存分歧表和裁决规则，不能只报告一个总体值掩盖某一维度失配。

## 4. 辅助方法的启用条件

### 4.1 语义相似度

只有运行环境提供可复现的句向量能力时启用。把每条文字与七维定义、正反边界说明和已经人工审定的当前任务主题原型比较。自动候选至少保存：嵌入方法标识、生成日期、文本预处理、第一和第二候选、相似度、候选差值、是否与词面规则一致。

阈值不得跨语言、跨领域照搬。先用当前任务的人工复核样本校准；无法校准时只作为候选排序，不得自动入分。

### 4.2 主题模型与聚类

当有效文字规模足够、需要发现代码簿遗漏主题时启用。输入应是去重后的同层级文字，避免把新闻、官方资料和短评论混成一个语料。根据主题词和代表文本人工命名，并与七维代码簿映射；模型生成的主题编号不是研究主题名称。

主题稳定性至少通过不同随机起点、主题数或抽样子集进行检查。小语料、极短文本或来源异质严重时，优先使用开放编码，不为“使用算法”而强行建模。

### 4.3 辅助语义判定

若当前平台具备通用语义分析能力，可用统一结构化指令返回：分析单位、主/次维度、情感、强度、否定、转折、弱化、反讽风险、证据句、置信度和待复核原因。不得指定某一固定供应商或固定模型；运行时记录实际环境能够提供的实现信息。

辅助判定必须与规则基线对照。两者一致且达到阈值时可进入自动候选；不一致时保留两套结果并复核。不得把系统自述置信度直接当作经校准概率，也不得让辅助判定生成原文不存在的体验细节。

## 5. 可执行文件与字段契约

正式任务先核对 Skill 内的评价协议与代码簿，再执行量化与编码解析队列：

```text
python scripts/quantify_text_semantics.py \
  --input "证据台账.csv" \
  --sources "来源台账.csv" \
  --codebook "assets/semantic-quantification-codebook.json" \
  --protocol "assets/evaluation-protocol.json" \
  --output "语义量化证据台账.csv" \
  --audit-output "语义量化审计.json" \
  --coding-queue "待编码解析队列.jsonl" \
  --place "本次研究对象" \
  --apply-auto-codes
```

脚本只对词表完整命中且通过阈值的规则候选回填空白维度和情感字段，不覆盖原生评分或已经人工确认的字段。部分命中和零命中进入编码解析队列，并保持复核未完成与正式评分资格为否；上游研究选择意图不构成评分旁路。所有词表命中、上下文规则与编码候选均写入相应机器轨迹。完成必要人工复核、重新派生正式资格、刷新计分数量并通过机器绑定 Evidence Audit（证据审计）后，才可带正式审计参数再次运行并生成平台评分输入。没有代码执行能力时也必须记录同一发布协议版本、代码簿版本和 SHA-256，并按锁定规则逐项人工填写相同字段，不能省略轨迹和复核状态。

最后把本次实际使用的规则固化为第三份 Office 成果：

```text
python scripts/build_semantic_rules_workbook.py \
  --codebook "assets/semantic-quantification-codebook.json" \
  --protocol "assets/evaluation-protocol.json" \
  --task-run-id "本次运行编号" \
  --place "本次研究对象" \
  --retrieval-date "YYYY-MM-DD" \
  --output "非量化文本量化评价规则_本次研究对象_YYYYMMDD.xlsx"
```

双编码表至少包含：`evidence_id,coder_id,primary_dimension,sentiment,stance_strength`。通过 `--agreement-input` 传入后，审计 JSON 输出分类 κ、名义 α 和顺序 α。

证据台账新增字段的含义：

- `native_rating_*`：来源原生数值及尺度。
- `semantic_method`：原生数值、规则代码簿、编码解析回退、辅助编码、人工编码或不适用。
- `semantic_language`：`zh`、`en`、`mixed` 或 `unknown`。
- `semantic_unit_text`、`semantic_clause_count`：实际分析文字与内部语句数。
- `lexicon_match_status`、`lexicon_match_trace`：维度与极性词表的完整、部分或零命中状态及实际命中轨迹。
- `coding_parse_status`、`coding_parse_candidates`、`coding_parse_trace`：编码解析启动状态、候选及其机器可读依据。
- `open_code_id`：词表缺口文本的稳定开放编码编号，不包含作者身份。
- `aspect_assignment_basis`、`aspect_confidence`、`dimension_rule_hits`：七维归属依据。
- `polarity_basis` 和各类 `*_hits`：极性与上下文运算依据。
- `semantic_score_raw`、`semantic_score_final`：连续候选分与整数分。
- `semantic_confidence`：语义判定确定度。
- `evidence_reliability`：证据可用程度。
- `aggregation_weight`：平台内聚合权重。
- `semantic_review_status`：自动候选、需复核、人工确认或不适用。
- `semantic_rule_trace`：逐线索贡献的机器可读轨迹。
- `coder_id`、`adjudication_status`：复核与裁决记录。
- `formal_scoring_eligible`、`formal_scoring_exclusion_reasons`：按发布版唯一资格规则形成的候选状态及排除理由。
- `formal_scoring_dedup_key`：以唯一 `primary_dimension` 和去重组形成的正式去重键。
- `platform_sample_status`、`included_in_platform_score`、`scoring_direction`：平台最低样本状态、是否实际计分和与最终 tendency 使用同一集合的正式方向。

正式评分维度归属只读取 `primary_dimension`。`dimension_tags` 只表示主题覆盖、检索缺口和定性解释，不增加候选或实际计分数量。一个原始文本同时包含多个可独立评价方面时，必须先拆成具有独立 `evidence_id`、独立语义文本、唯一主维度及独立情感分值的多个单元；未拆分的一条记录只能进入一个正式维度。

## 6. 报告与工作簿披露

DOCX 的研究方法、总体评价、七维分析和限制部分必须说明：评价协议版本、语义代码簿版本、代码簿 SHA-256、协议发布日期、发布校准来源与决策数、任务期不更新规则，双语词项和近义释义结构，文字量化方法、操作系数、词表零命中和编码解析数量、自动与人工记录数、低置信记录数、反讽或冲突记录数、一致性结果、语义分值与原生数值的区别。每个维度至少用一条可追溯证据解释主题—倾向—分值链条，不得只复述最终分数。

主 XLSX“样本明细”必须输出全部语义字段及正式评分注记；“主题编码”以当前任务归纳结果为准；“七维评分”只能使用先通过单条资格、再通过“平台 × 维度”最低样本门槛的实际计分记录。同一行的候选数、实际计分数、计分正中负数、有效计分平台数、tendency、转换分和加权分必须来自同一正式结果对象。“机器可读汇总”同时报告检索、主题覆盖、候选、实际计分、规则解析回退、零命中、未解、人工确认、待复核和低置信数量。待复核记录可以保留在工作簿，但不得悄然进入正式评分。

第三份规则 XLSX 的文件名固定为 `非量化文本量化评价规则_<地点>_<YYYYMMDD>.xlsx`，工作表顺序固定为：`评价协议摘要`、`发布校准来源`、`发布校准决策`、`极性词表`、`七维词表`、`上下文规则`、`编码解析规则`。不得删除、改名、换序或按任务临时改变表头。它必须导出发布锁定协议，记录本次任务编号和检索日期，并明确任务期没有规则变更。

## 7. 质量门与敏感性分析

交付前至少执行：

1. 随机抽查正、负、中性、混合各类记录及所有反讽风险记录。
2. 核对每个 `semantic_score_final` 能否由轨迹重算。
3. 比较“全部合格记录”“只保留高置信记录”“等权记录”三组维度结果；若方向或排名明显改变，降低结论确定度。
4. 检查同一词在不同语境是否被机械赋同一极性，尤其是商业、人流、旧、热闹、安静、真实和网红等语境词。
5. 检查低频维度是否因三条以下证据被错误补成中性分。
6. 核对语义量化行均有当前任务可见原文、来源 ID、真实 URL、去重组和复核状态。
7. 核对规则 XLSX 与证据台账使用同一 `task_run_id` 和检索日期，并核对规则 XLSX 的协议版本、代码簿版本及 SHA-256 与 Skill 发布资产一致。
8. 抽查所有 `zero_hit` 和 `coding_parse_fallback` 行均未计分，开放编码编号、候选与下一动作完整。

任何无法由原文、代码簿和轨迹重现的语义数值均视为不可交付。
