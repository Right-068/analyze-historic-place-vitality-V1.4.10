# 跨平台运行适配

本 Skill 面向支持 Skill、联网、代码执行和文件交付的桌面端、网页端及其他代理宿主。保持同一份完整源码，不建立平台分叉版。

宿主原生搜索、读页、浏览器、文件、Python 与 Office 是当前 Skill 的必要工具，不属于“其他 Skill”；禁止另加载或委托 Skill 不能禁用这些工具。首次只读根入口及 `orchestrator-lite.md`，具体协议按阶段加载。本文件数值仅解释已发布配置，不是第二个参数来源。

研究规则、审计规则和发布版代码高于执行 Agent 的自主判断。任何宿主都只能补充数据，不能补充资格；只能修复格式，不能修复结论；不得通过修改状态、脚本、评分或审计结果提前完成任务。初始化后先生成发布版完整性清单，正式 Skill 在整个运行期保持只读。

## 1. 按能力而非工具名适配

初始化前可调用 `run_research.py doctor --run-dir <工作目录>`：只做可清理探测，不创建任务。按发布 `requirements.txt` 安装精确依赖，包含时区数据；依赖版本不符必须明示。普通写入、原子替换和同步能力是运行条件；不能设置私密 ACL 只限制机密内容落盘，不阻断公开检索。分层、事务与错误恢复遵照 `storage-contract.md`，不得要求提权或全局安装。

| 所需能力 | 功能要求 | 正式任务是否必需 |
|---|---|---|
| 联网搜索 | 可提交多个查询并返回标题、摘要和真实 URL | 是 |
| 页面读取 | 可打开具体页面并判断正文、元数据、摘要和访问限制 | 是 |
| 宿主签章 | 可验证实际页面响应签章及连接事实 | 可选增强；普通工具可追溯来源不要求 |
| Python 3 | 可运行 Skill 内脚本 | 是，或有完全等价的代码能力 |
| XLSX 生成 | 可生成主数据工作簿和格式固定的语义规则工作簿 | 是 |
| DOCX 生成 | 可生成标题、表格和超链接结构正确的报告 | 是 |
| 文件下载 | 可把四份固定成果交给用户 | 是 |
| 最终引证 | 可向用户展示真实网页 URL，不依赖内部引用 ID | 是 |

平台缺少某个专有工具名不构成失败；选择等价功能。正式完成必须具备联网、页面读取、DOCX、XLSX 和文件交付能力。

仅当用户明确要求网络证据研究、活力评价、七维分析或正式研究报告时执行完整任务；普通地点介绍、旅游攻略、简单问答和单一平台摘要不触发。常规参数未指定时采用发布默认值。

## 2. 解析 Skill 路径

默认统一调用 `scripts/run_research.py execute-next-action` 启用并恢复顺序模块；按返回的动作信封和自包含字段合同提交完整分派批次。模块命令由程序选择，宿主不猜 API；批量模式的旧单项公共方法及 submit 被代码拒绝。事实背景只保留来源，用户候选才抽取编码；没有可信人工决定时未确认条目正式不计分并继续原审计。合同见 `batch-pipeline.md`。内部调用编号缺失时留空，真实登记/重读通过后才确认能力。

每个窗口完成后按 `AUTO_CONTINUE` 自动下一动作，不因阶段进展结束回复。候选格式、单页失败、重复或无结果走 `SOFT_RETRY`，有界修复、跳过失败项或继续其他公开结果，不升级为用户任务阻断。只有整体能力/存储失效或不可恢复状态是 `HARD_BLOCKER`；真正缺用户信息或授权才是 `USER_INPUT_REQUIRED`。`COMPLETED` 必须经正式验收封印。宿主硬回合限制不能绕过；原子事实和窗口已落盘，重新获得执行机会后恢复同一目录，不重检已完成项。

研究输出写入用户本次指定位置。网页端使用临时沙箱时，先在本次任务目录生成，并在会话结束前提供四份可下载成果；不要声称临时文件已长期保存。

## 3. Python 和依赖

核心检索计划、审计、评分和联合验收尽量使用 Python 标准库。Office 文件生成需要：

- `xlsxwriter`：生成七表主 XLSX、固定七表规则 XLSX、样式、公式和雷达图；
- `python-docx`：生成十五部分 DOCX、表格和可点击来源链接。
- `idna`：统一执行 IDNA 2008／非过渡式 UTS #46 域名处理，不回退到兼容折叠主机的旧转换；发布依赖见根目录 `requirements.txt`。
- `cryptography`：用于可选宿主页面收据及可信人工决定的公开验证；缺失不阻止普通工具检索和自动证据路径，但已提交签章必须完整验证，不能降级绕过。人工身份和权限只读发布前配置，未配置时只保留相关待复核记录。

根据环境使用当前解释器（命令行可为 `python` 或 `python3`）；子进程和测试必须继承当前解释器，不得写死某台机器的 Python 路径。最低支持 Python 3.11。开始正式生成前运行等价依赖探测：

```text
python -c "import idna, xlsxwriter, docx; print('dependencies_ready')"
```

若依赖缺失且平台允许安装，使用该平台批准的包管理方式补齐。若平台已提供等价的原生文档生成库，可以替代，但必须保持字段、样式和验证规则一致。若无法创建真实 DOCX、两份 XLSX 和实时详细运行日志，明确能力限制，不能把 CSV、JSON、Markdown 或聊天文本称为最终成果。

统一使用 UTF-8 读取和写入文本；CSV 可用 UTF-8 with BOM，但仅为机器中间文件，不应直接在电子表格软件中打开外部原文。用户查看使用已按文本安全写入并验收的正式 XLSX。宿主默认编码不是 UTF-8 时，启用该宿主的 UTF-8 Python 模式，不修改文字内容迁就乱码。

脚本逻辑不依赖 PowerShell、Bash、盘符、反斜杠、Office COM、浏览器品牌或平台 SDK。路径通过命令行参数传入。

## 4. 使用联网工具

采集前按 `host-page-receipts.md` 检查真实搜索与页面读取能力；`host_receipts.py --capabilities` 只查看可选签章及工具实测状态，未知能力应先实测而不是退出。正常桌面端采用 `tool_traceable`：保存实际页面结果引用、请求/最终 URL、标题、带时区访问时间和原始结果文件，由采集器绑定任务、执行与快照哈希。真实宿主提供签章时采用 `host_verified` 增强级；签章无效不得降级。没有当前工具读取依据的 `self_reported` 材料不进入正式来源。不得自签、补 IP 或把搜索卡片当成已读正文。观察输入仅可使用共享 Schema 白名单。

无论平台把功能命名为“搜索”“深度搜索”“浏览”还是其他名称，都遵循唯一正式阶段顺序：`INITIALIZE → SEARCH → EVIDENCE_BUILD → SEMANTIC_QUANTIFICATION → EVIDENCE_AUDIT → SCORE → REPORT_BUILD → VALIDATE → DELIVER`。具体执行为：

1. 由当前状态和已提交计划创建真实检索任务，使用 `execution_facts.py` 记录实际尝试及唯一执行身份；
2. 打开原始页面，判断读取状态和内容层级；
   优先保存真实页面工具返回的可见纯文本。只有 HTML 源码时，由采集器标注静态可见性；依赖渲染的内容保留候选并使用真实页面工具重读，不把静态文本自动当作用户评论，不要求普通纯文本额外提供 CSS 或连接事实。
3. 用 `source_capture.py capture --tool-result ...` 自动登记本次实际页面工具响应并核验绑定，或使用可选宿主签章路径；确定性提取并脱敏后保存追加式采集事件、内容寻址快照、请求与最终内容身份、查询编号、来源类型、统一平台与页面实体。工具结果文件只包含实际 `response_text`；登记字段由程序派生，不能从普通项目文件补造。含敏感信息的原始结果单独限权保存，普通公开正文使用完整性存储，并发写入由脚本跨进程序列化；
4. 在暂存层建立候选来源和候选证据；
5. 由 `pre_admission_audit.py` 统一检查定位、统一 `platform_id`、采集层来源类型、页面实体、内容层、无正文原生数值完整性和碰撞，整批原子提升为不可变正式来源与原始证据；
6. 运行发布版语义量化，必要时通过固定人工复核合同和追加式变更台账裁决，再由发布版算法完成正式资格派生；
7. 刷新逐查询新增与累计实际计分数；
8. 首次运行正式证据审计；
9. 审计通过后再评分；返回 `needs_iteration` 时完整返回检索阶段，任何评分、报告和交付入口均不得旁路；
10. 从冻结工件编译机器报告事实，检查定性叙事后再组装正式报告数据和 Office 成果。

非量化文字定量评价直接读取 Skill 内发布锁定的 `assets/evaluation-protocol.json` 与 `assets/semantic-quantification-codebook.json`，核对评价协议版本、代码簿版本和 SHA-256。发布校准来源和决策属于 Skill 版本资产，不与单次地点任务的日期或 `task_run_id` 重新绑定。任何宿主均不得在任务中在线改写词表、阈值、权重或上下文规则；未命中表达进入编码解析和复核队列，只能作为未来 Skill 版本发布校准的候选。

检索开始时生成唯一 `task_run_id`。任何平台的模型记忆、旧对话摘要、旧报告、旧台账和旧评分都不得成为本次证据；只有本次任务实际打开、核验并写入同一运行编号的内容才能进入结果。平台无法关闭内部记忆功能时，仍须在研究层显式忽略其内容，不把它转写为事实、链接、样本、数量或结论。

平台生成的搜索摘要、AI 摘要或“精选评论”必须记录选择机制：

- 搜索摘要标为 `snippet_only`；
- AI 汇总只算一个摘要，不拆成多个用户；
- 平台按相关性或新旧程度选择的评论可作为可见单元，但必须记录排序偏差；
- 页面宣称汇总多人意见但不提供逐条内容时，只计一个来源页。

最终 DOCX 和两份 XLSX 只保存真实页面 URL。工具内部搜索编号、缓存标识或引用 ID 只用于当前运行时继续打开页面，不能替代 URL。页面门槛按规范 URL、最终跳转、内容指纹和可信独立出现复核形成的机器页面实体统计，不按来源编号统计。两份 XLSX 的用户可见表头、枚举、状态与说明在有准确中文表达时必须显示中文，稳定机器字段只保留在机器可读层。

## 5. 批量和长任务适配

150 个页面实体是独立正式页面门槛。正式计分证据按所选逐维目标计算：中、中高、高分别至少为每维 25/40/60 个，七维理论最低总量为 175/280/420；默认中高，因此默认理论最低为 280，100 仅作历史兼容警戒下限，不是完整评价的正常终止规模。每维还分别要求来自同一计分集合的独立来源页面和实际来源类型；总量不能补偿单维缺口。检索证据、主题覆盖证据、评分候选证据和实际计分证据必须分开记录；`dimension_tags` 只用于主题覆盖，正式门禁和计分只按唯一 `primary_dimension`。候选证据只有在所属“平台 × 维度”达到发布协议的最低样本数后才成为实际计分证据。支持并行搜索的平台可并行执行不同来源类型或主题查询，但每条结果仍需统一写入台账并全局去重；同一查询全局只计一次，可由 `query_dimension_targets` 贡献多个真实维度覆盖。没有并行能力的平台按批次执行，不降低页面、来源类型或审计标准。

开始长任务时先按能力判断宿主类型，不根据产品名称猜测：

| 能力 | 运行策略 |
|---|---|
| 可核验的持久后台工作流 | 实际启动并保存运行标识；后台结束前不把排队或计划称为成果 |
| 可调整代理工具轮次或长任务预算 | 选择适合深度研究的预算，避免使用快速查询的低轮次设置 |
| 同一回复可连续调用工具 | 每次工具结果后立即调用下一批，直到终态 |
| 只有普通对话回复 | 未完成时抑制阶段总结；回复结束即视为任务已停止，不能声称后台继续 |

模型能理解长任务不代表宿主会提供无限工具轮次。检测到当前宿主存在单轮上限时，优先减少工具轮次消耗：

- 单次搜索能力允许时并行提交多条互补查询；
- 单次页面读取能力允许时批量打开多个候选页面；
- 同批结果先按规范 URL、最终跳转、内容指纹、页面实体和证据语义去重，再批量写入来源与证据台账；
- 把搜索、读取、编码、审计和生成的事实写入文件，不用长篇聊天进度重复；
- 每批后调用 `manage_run_state.py checkpoint`，先核对发布版哈希与合法阶段迁移，再记录真实累计数量和精确下一动作；
- 只有真实后台运行标识存在时才使用“后台运行”措辞。

基础检索完成后必须先量化、复核、派生和刷新，才能以正式审计判断缺口。任一维尚未达到运行状态锁定的目标且未通过适用强终止审计时，任何平台均须自动进入相应深度迭代，不等待用户确认。缺口诊断必须形成平台×维度矩阵，不得用 `dimension_tags` 的宽口径数量掩盖缺口。计划记录与执行记录分离，只有通过共享记录级校验器的真实尝试计入轮次、预算、覆盖、低增益或穷尽；`not_run`、`planned`、`queued`、`cancelled`、`skipped` 和凭据不完整记录全部排除，且任一无效记录阻断正式终态。查询生成器读取历史原字段并重新派生规范意图，落盘 `normalized_query_intent` 只作一致性断言。发布预算以“独立意图/实际尝试/重试”表示：基础 120/144/24，深检全局 300/360/60，全流程重试储备 84，实际尝试安全上限 504；深检单轮 60/72/12，单维累计 48/62/14，单维单轮 10/13/3，最多 5 轮。重试不增加独立意图覆盖；任一超限先于目标或终态判定硬失败。基础与深检分账，规划器按剩余必需轮次和重试储备预留动态配额，不机械固定每轮查询数。

阻断、无结果、低增益和穷尽按维度、平台、来源类型、路径、查询意图、正负路径、主体和时间情境限定；单条记录不能全局终止。预算、轮次或路线到达只阻止继续生成非法计划，不授权受限交付；每个不足维度仍须分别通过发布版独立穷尽审计及其 `exhaustion_machine_binding`，否则保持非终态。停在中置信度至少需要累计五轮、三轮增强、每轮十条、六类目标来源和主体/时间/正负覆盖的独立审计；单维“穷尽后低置信度”至少需要四轮、每轮 8 条、5 类目标来源和查询—页面—证据跨台账独立审计。普通聊天文字、待办清单、预算标记或只写 `exhausted` 不能降低门槛。

持久化查询计划必须使用当前 `task_run_id`，并绑定对象、轮次、审计、状态、已执行历史、检索控制与生成器哈希；计划和绑定伴随文件在跨进程锁中原子写入。不同宿主进程只能复用绑定完全一致且内容哈希未变的计划，跨任务、过期审计、损坏伴随文件或部分写入均失败封闭。

所有宿主共用 `execution-facts.md`：`execution_schema_context` 由实际状态锚点和计划登记派生并显式传入各消费者，不能依据日志字段自行猜测。旧任务须有受限日期依据和显式迁移记录；新执行始终使用严格字段。运行根路径不进入公共上下文哈希；复制任务后从当前状态路径重新绑定。物理重排不改变机器结论，但实际文件哈希变化仍需合法写入登记。执行日志中断恢复必须完成原事务，不得重新发起已完成查询来替代恢复。

长任务应定期保存检索日志、来源和证据 CSV，避免依赖聊天记忆恢复计数。跨会话继续时只能重新加载同一任务运行编号下的下列文件：

1. 检索日志；
2. 来源台账；
3. 证据台账；
4. 平台评分输入和输出；
5. 当前报告 JSON；
6. 审计结果；
7. `manage_run_state.py` 生成的运行状态 JSON。
8. 发布版完整性清单与实时详细运行日志。
9. 受保护工件写入台账、真值冻结清单、全链预检和已产生的验收错误清单。

运行目录迁移时，从当前状态文件位置解析所有运行根相对引用，核对内容哈希后重新运行审计和评分脚本，确认迁移前后结果一致；含中文、空格或不同盘符不得影响身份。若状态为 `paused_by_host_limit`，明确说明当前没有后台进程；宿主提供恢复入口后直接从 `next_action` 继续，不要求用户重复输入地点、时间范围或常规参数。

## 6. 登录和受限页面

让用户在当前平台允许的浏览器或会话中自行完成登录。不得跨平台传递、导出或复用登录状态，不得把 Cookie、Token、验证码或授权链接写入任务目录。

登录只改变“是否能正常查看”，不改变批量采集权限。遇到验证码、人机核验、反爬、权限或频率限制时停止该来源路径，并在所有平台使用同样的受限状态记录。

大众点评和小红书默认剔除，不要求任何平台为了访问它们改变浏览器、接口或登录方式。统一理由是：未登录访问通常受限；研究另有独立获取路径；本结果后续与两类独立结果综合，默认排除可避免重复样本、重复计数和证据层混淆。只有用户明确要求且页面合法、正常可读时才纳入，并与独立结果去重。

## 7. 文件生成与交付

核心中间格式是 UTF-8 CSV、JSON 与 JSONL。生成时以不可变采集、正式当前有效视图和冻结派生物为唯一事实来源：

```text
python scripts/source_capture.py ...
python scripts/pre_admission_audit.py ...
python scripts/quantify_text_semantics.py ...
python scripts/refresh_search_log.py ...
python scripts/audit_evidence.py ...
python scripts/compile_report_truth.py ...
python scripts/assemble_report_data.py ...
python scripts/build_research_workbook.py ...
python scripts/build_docx_report.py ...
python scripts/validate_deliverables.py ...
```

四份固定成果必须位于同一用户指定目录。文件生成后不要只检查“存在”，必须重新打开 Office 包，并读取详细运行日志、机器绑定审计和发布版完整性清单，核对结构、页面数、公式、图表、标题、表格、来源链接、状态、隐私和跨文件一致性。

若平台能生成但不能长期保存，立即把可下载链接交给用户并说明平台临时文件的保存边界。

## 8. 平台元数据

`agents/` 内的界面元数据供识别相应格式的宿主展示名称和默认调用语；其他宿主可以忽略。所有宿主都以 `SKILL.md` 的 frontmatter 和正文作为核心触发与执行规范。

不要为任何具体宿主复制并改写研究协议、评分规则或模板。平台适配只处理工具调用和文件传递，不改变立即执行、本次任务证据隔离、只读发布版、固定状态机、150 页门槛、由所选逐维置信等级派生的正式计分证据目标、逐维中置信度门槛、强独立穷尽审计、深度迭代、来源多样性、七维评分或 DOCX/XLSX/TXT 交付标准。默认中高目标对应七维理论最低 280；历史兼容值 100 不得被宿主解释为完整终止目标。

## 9. 宿主无关的正式写入与资源保护

执行和更正事务使用同一运行级协调器。恢复入口为 `execution_facts.py --recover-transactions`，配合同一状态和写入台账；待恢复时阻断新计划及其他正式写入，不能换进程绕开。执行必须晚于任务、SEARCH、计划登记和本轮准入的受保护时间，不能仅把几项观察时间互相排序后宣称有效。

任何宿主都必须使用同一状态授权、受保护工件台账、真值冻结、全链预检和交付封印。宿主允许创建任意临时脚本或工作文件，不代表这些文件可以进入正式链；正式来源只由登记脚本、合法阶段和匹配哈希共同证明，不能依赖执行 Agent 的声明、文件名或文件存在性。

宿主没有可信人工签章能力时，人工待复核记录保持 `review_required`，不能由模型或普通脚本升级为 `human_confirmed`。宿主能够接收真实人工决定时，也必须通过固定合同和受信任密钥校验，随后交回发布版确定性派生链。

跨会话恢复先验证发布清单、状态—日志绑定、受保护写入台账和冻结清单，确认所有当前文件哈希仍与检查点一致。所有 `run_relative` 路径由同一安全解析函数处理：拒绝绝对路径、盘符相对路径、UNC、`..` 和经符号链接或目录联接解析后逃逸运行根的路径；读取与写入使用同一约束。复制运行目录后当前状态文件所在根优先，旧绝对路径只可在当前副本缺失时进入显式、复制式、留痕迁移，不能继续跨目录引用或写回旧目录。若审计已为 `retrieval_terminated_with_shortfall`，恢复时保持终态，除非执行显式受控重开。若已经进入 `VALIDATE`，恢复后仍实行上游绝对只读；不能把重新运行上游脚本视为恢复。第一轮验收失败后最多执行一次集中根因修复和一次下游整链重建，第二轮失败即停止。并行、后台或批量能力只能减少执行开销，不能增加 validation 轮次或改变终止条件。
