## 1. 最终文件与中间文件

正式交付只包含：

1. `历史文化活力分析报告_<地点>_<YYYYMMDD>.docx`
2. `网络检索与量化编码_<地点>_<YYYYMMDD>.xlsx`
3. `非量化文本量化评价规则_<地点>_<YYYYMMDD>.xlsx`
4. `详细运行日志_<地点>_<YYYYMMDD_HHMMSS>.txt`

以下均为中间文件，不得替代最终成果：

- 检索计划 CSV；
- 检索日志 CSV；
- 来源台账 CSV；
- 证据台账 CSV；
- 发布校准候选清单 JSON；
- 待编码解析队列 JSONL；
- 评分输入和输出 JSON；
- 结构化报告 JSON；
- 审计 JSON；
- Markdown 草稿。

中间文件可以留在任务工作目录供复核，但不得冒充或替代四份固定成果。详细运行日志必须从初始化开始按真实东八区时间追加，不能在任务结束后补造。

所有 Excel 输出均执行“可中文则中文”：工作表名、表头、布尔值、状态、来源类型、读取状态、情感、语义方法、复核状态、平台样本状态、检索终止原因、限制和说明在存在准确中文表达时必须填写中文。英文稳定字段、枚举和 JSON 只保留在明确标注的机器可读层；不得以英文机器值替代用户可读中文，也不得把机器字段翻译后反写正式台账。

## 2. 主 XLSX 的七表架构

工作表名称和顺序固定为：

1. `样本明细`
2. `来源页面`
3. `主题编码`
4. `七维评分`
5. `检索日志`
6. `数据限制说明`
7. `机器可读汇总`

### 样本明细

一行一个证据单元。保留本次任务运行编号、内部编号、所属来源页面、页面标题、时间、作者类型、内容层级、地点相关性、推广判断、有效性、情感、摘要原文、必要摘录或匿名化摘要、主题、主要和次要维度、来源 URL、评分资格、情感分值、互动背景和备注。“摘要原文”应保存本次页面中实际可见、能够支撑编码且合规的原始摘要或原文片段；不得用模型生成的概括伪装成原文。主体标签使用本地居民、商户、游客、传承人或文化实践者、管理者、专业人士或其他公众；时间标签使用当前状态、历史回忆、改造前后比较、长期变化、工作日、周末、节假日、节庆活动期间、白天或夜间，可按实际证据组合填写。

同表还必须包含：原生数值、原生量表上下界、语义量化方法、语义语言、语义分析单位、子句数、词表命中状态与轨迹、编码解析状态、候选与轨迹、开放编码编号、维度判定依据、维度判定置信度、维度规则命中、极性依据、否定命中、程度命中、转折命中、弱化命中、反讽风险、语义连续分、语义整数分、语义置信度、证据可靠性、平台内聚合权重、语义复核状态、规则轨迹、编码者编号和裁决状态。还要固定包含 `dimension_tags` 对应的“主题维度标签”、正式评分候选资格、排除原因、正式去重键、平台样本状态、是否实际进入平台评分和正式计分方向。没有使用某项时留空或写规范的 `not_applicable`，不得删除字段。

“主要维度”是唯一正式评分归属；“主题维度标签”仅用于主题覆盖和定性说明。原始文本同时涉及多个独立方面时，应先拆成多个独立样本行，每行具有独立证据 ID、语义文本、主维度和情感分值，不得让同一行依靠多个标签重复计分。

用户信息只用内部匿名编号。完整评论和回复不可被搜索摘要、AI 摘要或平台显示总数替代。

### 来源页面

一行一个检索页面，并包含至少 150 个去重相关页面。字段覆盖：

- 来源编号、地点和实体层级；
- 平台、域名和来源类型；
- 标题、发布时间、检索日期和页面 URL；
- 检索记录编号、实际检索词和结果排序；
- 读取状态、内容层级和选择机制；
- 相关性、用户来源、推广和评分资格；
- 评分范围、去重组、原始来源和证据定位。

这是“所有检索页面”的主表。无正文、仅摘要、仅元数据和不可访问页面也记录，但如实标注状态，不进入评分。

### 主题编码

一行一个归一化主题，包含主题编码、归属维度、方向、定义、全部有效提及数、量化提及数、正中负混合计数、有效内容占比和代表性匿名摘录。

计数列使用公式并写入缓存值，使不支持公式重算的查看器也能看到当前结果。

### 七维评分

七个维度各一行。同一行的正式评分字段必须全部来自同一个跨平台维度结果对象和同一份实际计分集合，至少包含：初始研究权重、评分证据状态、实际权重、检索有效证据数、主题覆盖证据数、评分候选证据数、实际计分证据数、计分正中负数量、有效计分平台数、平台总数、平台最低样本规则状态、倾向分、转换分、加权分、正式评分置信度、依据、提及比例和提及等级。初始研究权重依次固定为历史文化感知 15%、在地文化特征 15%、生活文化延续 20%、文化实践体验 15%、场所氛围体验 10%、保护活化感知 15%、承载治理体验 10%，并固定追加最低有效证据门槛、独立来源页数、最低来源页门槛、来源类型数、最低来源类型门槛、定向深检轮次、最低置信度要求、优先置信度目标、中置信度终止审计、中置信度终止依据和缺口或穷尽说明。

中置信度最低门槛为 25 个实际计分证据、12 个同集合独立来源页和 3 类实际来源；中高为 40/20/4，高为 60/30/5。中仅为最低要求：未经增强终止审计时写“必须继续本维增强检索”并隐藏定稿状态；中高或高写“优先目标达标”；通过五轮累计、三轮增强等强审计后方可写“中置信度审计终止”。低于中且未通过独立穷尽审计时写“必须继续本维深检”；经强审计确认穷尽后写“穷尽后证据不足”。不得以 50 分填补、删除维度或重分配权重。右侧包含七维雷达图，图表数据只来自七维正式转换分；空分保留为图表缺口或显著标为数据不足，不得绘制为 0。

### 检索日志

“检索日志”同时保留计划记录和执行记录，但通过“记录类型”“计划编号”“执行编号”明确分离。只有实际启动并具有执行凭据的记录参与查询数、轮次、预算、覆盖、低收益、阻断和穷尽；无结果、受限、部分完成和失败的真实尝试可以计入资源消耗并保留不同业务含义，`not_run`、`planned`、`queued`、`cancelled`、`skipped` 不计入。执行记录必须能通过 `检索记录编号` 与“来源页面”关联，并记录规范查询意图、迭代轮次、目标缺口、迭代模式、本轮前正式评分置信度、该轮新增与累计实际计分证据数、下一步动作和作用域明确的终止状态。任一维未达到所选目标或未通过适用强终止审计时自动继续相应缺口检索，不得等待用户确认。面向用户的字段和值有准确中文表达时全部显示中文；稳定机器值只保留在机器可读层。

### 数据限制说明

至少包含公开网络样本边界、搜索排序、来源结构、时间覆盖、访问限制、推广识别、去重、群体偏差、情感分母、评分可信度和默认来源处理。默认来源处理必须说明两类平台的未登录访问限制、另有独立获取路径、后续综合分析用途，以及排除如何避免重复样本、重复计数和证据层混淆。

### 机器可读汇总

一行一个地点，保留本次任务运行编号、查询数、页面数、150 页门槛、读取状态、来源类型、用户页面、证据数、实际计分证据目标、评分候选证据数、实际计分证据数、是否达标、样本缺口、深度迭代轮次、迭代结果、计分正中负数量、七维分、“历史文化活态传承感知评价”结果层、底线性问题检查、平台等权分、样本加权分、建议分、可信度、时间范围和边界声明，并报告正式评分链标识、语义规则记录数、编码解析回退数、词表零命中数、编码候选数、仍未解数、原生数值记录数、自动通过数、人工确认数、待复核数、低置信数和反讽风险数。还要固定输出最低维度置信度、高/中高/中维度数、中置信度审计终止数、独立穷尽后低置信维度数、待深检维度数、增强目标、硬缺口目标和完整机器可读逐维评分审计 JSON。

关键计数使用公式并写入缓存值。公式、正文和台账之间不得冲突。

## 3. 规则 XLSX 的固定七表架构

文件名固定为 `非量化文本量化评价规则_<地点>_<YYYYMMDD>.xlsx`，由 `scripts/build_semantic_rules_workbook.py` 从发布锁定的评价协议与语义代码簿生成。不得改名、删除工作表、换序、增加任务自定义列或在任务期临时修改规则。工作表和精确表头固定如下：

1. `评价协议摘要`：`地点名称｜任务运行编号｜本次检索日期｜评价协议版本｜语义代码簿版本｜协议发布日期｜发布校准模式｜校准查询数｜可读方法来源数｜独立来源域名数｜校准决策数｜语义代码簿SHA256｜任务期规则变更｜规则应用说明`。
2. `发布校准来源`：`来源编号｜页面标题｜发布机构｜来源域名｜来源URL｜检索日期｜读取状态｜方法领域｜发布校准发现`。
3. `发布校准决策`：`决策编号｜动作｜规则目标｜决策理由｜依据来源编号｜是否改变锁定代码簿`。
4. `极性词表`：`概念编号｜极性｜基础权重｜语言｜词项类型｜词项｜中文释义｜英文释义｜机器读取路径`。
5. `七维词表`：`维度编号｜中文维度名｜英文维度名｜初始研究权重｜语言｜词项类型｜词项｜中文释义｜英文释义｜机器读取路径`。
6. `上下文规则`：`规则类别｜规则编号｜语言｜词项或参数｜参数值｜作用范围｜机器处理｜规则说明`。
7. `编码解析规则`：`顺序｜触发条件｜输入｜处理规则｜输出｜阈值或上限｜评分政策｜复核要求`。

“评价协议摘要”恰好一行，必须含协议版本、代码簿版本、SHA-256 并写明任务期规则变更为“否”；“发布校准来源”不少于三行且覆盖至少两个域名；“发布校准决策”不少于一行；“极性词表”和“七维词表”必须同时包含 `zh`、`en`、近义释义、双语定义和机器读取路径；“七维词表”恰好覆盖七个维度；“上下文规则”至少覆盖否定、程度、转折、弱化、反讽风险和参数；“编码解析规则”固定八行，并明确候选确认前保持待复核、正式评分资格为否且不得进入平台计分。

空白结构模板位于 `assets/非量化文本量化评价规则_模板.xlsx`，仅用于查看格式。正式成果必须包含发布校准来源、决策、锁定词表和参数，不能交付空白模板。

## 4. XLSX 视觉样式

工作簿统一使用以下视觉规范：

- 表头字体：Carlito；
- 表头字号：10；
- 表头字体：白色、粗体；
- 表头填充：深蓝色 `#17324D`；
- 表头对齐：水平和垂直居中；
- 表头自动换行；
- 表头行高：34 点；
- 数据行建议高度：25.5 点；
- 数据单元格：Carlito 10 号、顶端对齐、自动换行；
- 隐藏网格线；
- 每个明细区使用带筛选的 Excel 表格；
- URL 显示为可点击蓝色下划线；
- 列宽按内容类型设置，长标题、摘要、URL 和说明列加宽；
- 情感分和七维得分允许条件格式；
- 七维评分包含雷达图。

主工作簿空模板位于 `assets/网络检索与量化编码_模板.xlsx`，规则工作簿空模板位于 `assets/非量化文本量化评价规则_模板.xlsx`。模板不含用户原样本数据，不把单一平台字段写死为通用规范。

## 5. XLSX 数据和公式规则

标题、原文、查询、备注、限制及其他外部文本一律显式写为字符串，关闭自动公式和自动 URL 识别；以 `=`、`+`、`-`、`@`、制表符或换行开头也不解释为公式。不得更改上游原文来规避注入。超链接只在专用 URL 位置经过公开 HTTP(S) 检查后显式写入，不允许文件、脚本或私网关系。真实数字保持数字，固定程序公式保留原有位置、算法和缓存。

联合验收重新打开 OOXML，核对固定公式白名单及单元格位置，拒绝外部工作簿关系、宏和不安全超链接，并正确还原标准文本转义。CSV/JSONL 是保持原文的机器中间层，不宣称可安全双击打开；面向用户的表格交付只用已经执行文本安全规则的 XLSX。

- 所有面向用户的工作表名、表头、状态、枚举、说明和限制内容，只要存在准确中文表达就必须显示中文；稳定机器字段与协议枚举可以保留在“机器可读汇总”等机器层，不得用英文替代可用中文；
- 所有 CSV 输入使用 UTF-8 with BOM 或 UTF-8；
- 来源 URL 必须是绝对 `http(s)` 地址；
- 去重相关页面数按发布版生成的规范化 URL 哈希；`dedup_group` 仅作辅助审查，不能增加页面数；
- `full` 和 `partial` 才可贡献正文证据；
- `snippet_only`、`metadata_only` 和 `inaccessible` 不进入用户情感评分；
- 主题计数和机器汇总公式必须有缓存结果；
- 百分比单元格使用百分比格式，不把字符串和数值混用；
- 缺失分数使用空单元格和明确状态，不使用零值伪装；
- 候选数、实际计分数、计分正中负数量、平台状态、倾向、转换和加权分不得从不同统计对象拼接；
- 工作簿计算模式设为自动；
- 表名固定且唯一：`DetailTable`、`SourcePagesTable`、`ThemesTable`、`SearchLogTable`、`LimitationsTable`、`MachineSummaryTable`；
- 最终文件中至少存在一个七维图表和二十个公式；
- 保存后必须重新解析工作表、表头、公式、图表和来源 ID。

## 6. DOCX 版式与结构

DOCX 使用 A4 纵向；上、左页边距 2.4 厘米，下、右页边距 2.2 厘米，页眉页脚距离 1.1 厘米。字体只允许黑体、宋体和 Times New Roman：封面主标题 24 磅黑体、副标题 14 磅黑体、检索日期 11 磅；三级标题以上使用黑体，字号依次为 16、14、12 磅；正文中文 10.5 磅宋体，拉丁字符与数字使用 Times New Roman，1.5 倍行距。正文英文词、缩写或短语须就近附中文释义，网址、任务编号和机器行除外。

封面后分页，目录列出研究口径说明和十五章；目录后再次分页。研究口径说明使用未编号 `Heading 1`，其后十五个编号章也使用 `Heading 1`。第 5 节七个维度使用 `Heading 2`，每维恰好三个 `Heading 3`：前两个为主要正面评价和主要负面评价，第三个由本维证据决定。

第 5 节由顶层 `dimension_analyses` 自动排版。八个结构化字段为 `positive`、`negative`、`differences`、`fact_perception`、`mechanism_analysis`、`counterevidence`、`uncertainty_boundary`、`synthesis_judgment`。每维必须使用唯一框架中的原始定义和编码边界，并显示固定二十九项标签：作用机制、反证与替代解释、不确定性与适用边界、综合判断、初始研究权重、高频主题、提及率、倾向、转换、证据充分度、检索有效证据数、主题覆盖证据数、评分候选证据数、实际计分证据数、计分正中负构成、有效计分平台、来源页、来源类型、维度置信度、最低要求、优先目标、证据状态、定向轮次、独立穷尽审计、中置信度终止审计及依据、编码边界和代表性来源；来源为真正的外部超链接。只要涉及评分样本量、计分构成、有效平台、正式置信度和分数，必须读取正式评分结果；定性段落可以综合更广的检索证据与主题覆盖，但要明确口径。

正面段不少于 100 个中文字符，负面段不少于 90 个中文字符，第三模块与事实对照合计不少于 180 个中文字符，作用机制不少于 120 个，反证与替代解释不少于 100 个，不确定性与适用边界不少于 100 个，综合判断不少于 120 个；每维不少于 1000 个中文字符，第 5 节不少于 5000 个中文字符。第 13 节至少七段且不少于 1500 个中文字符。来源清单之前的叙事和分析表格合计不少于 12500 个中文字符，建议控制在 13500—16500；完全重复、近重复、跨维套壳、结论复制和低质量凑字均导致验收失败。

DOCX 恰好十二张表，表头、职责和顺序按 `references/report-schema.md`。表格采用深蓝表头、白色粗体和交替浅色数据行。第 14 节从来源台账生成全部来源行并设置可点击链接；第 15 节只有一行十九字段机器结果。

## 7. 结构化报告数据

正式报告数据不得由模型直接整体填写。先运行 `compile_report_truth.py`，从冻结来源、当前有效原始证据、正式评分证据、检索日志、维度审计、平台评分、综合评分、评价协议和语义代码簿生成 `report_truth.json`。其中数量、比例、日期、查询轮次、逐维平台计数、倾向、转换分、加权分、综合分、权重、阈值、协议标识和机器状态均为只读机器事实。

模型只能依据 `report-narrative-template.json` 生成定性叙事，且不得复写任何机器数值或状态字段。`assemble_report_data.py` 先检查叙事字段、来源引用、重复度和机器事实越权，再把叙事与 `report_truth.json` 合并到 `report-data-template.json`。正式 `report-data.json` 必须同时登记机器真值、叙事和自身的 SHA-256；叙事最多两轮、报告数据最多两次提升，未收敛时不得继续生成 Office。

## 8. 生成顺序

1. 初始化唯一 `task_run_id`、发布版完整性清单、受保护工件写入台账和实时详细运行日志；运行期间正式 Skill 保持只读；
2. 页面读取先写不可变采集清单与内容寻址快照；候选来源和候选证据进入暂存层，经准入前审计整批通过后，由唯一提升入口原子追加 canonical 来源与原始证据并物化当前有效视图；
3. 核对发布锁定的 `evaluation-protocol.json`、语义代码簿版本及 SHA-256；单次任务不联网更新或改写评分规则；
4. 使用发布锁定代码簿运行 `quantify_text_semantics.py`，保存词表命中、编码解析、语义轨迹、置信度和复核队列；
5. 需要辅助编码、人工复核或双编码时，只通过固定决定合同和追加式变更台账完成裁决，再重新运行发布版确定性派生；不得手填评分资格和分数；
6. 运行 `refresh_search_log.py`，由正式计分字段刷新逐查询新增与累计计分数量；
7. 首次运行正式 `audit_evidence.py`。如返回 `needs_iteration`，状态机立即回到检索阶段，并重新执行证据构建、量化、必要复核、刷新和正式审计。总体样本短缺按契约至少三轮；单维停在中时执行五轮累计、三轮增强、每轮十条及跨台账强审计，低于中时至少四轮、每轮八条、五类目标来源及独立穷尽审计。只有总体样本和七维门禁均成为可交付终态才进入下一步；
8. 审计通过后冻结来源、原始/语义/可信复核/正式证据、检索日志、机器审计、评价协议和语义代码簿；
9. 由正式评分证据台账自动生成平台评分 JSON；单条候选、平台最低样本门禁、正中负计分数量和倾向值禁止手填。评分入口重新验证同一运行的机器绑定审计、发布协议版本和评分输入封印后运行 `calculate_scores.py`；任何 `needs_iteration` 维度都会阻止评分，缺维权重不得重新归一；
10. 把平台评分输入与综合评分输出追加到真值冻结清单，运行 `compile_report_truth.py` 生成只读机器报告事实，再执行全链 preflight（预检）；无效时不得生成 Office；
11. 完成数据限制 CSV；按固定叙事合同生成定性字段，由 `assemble_report_data.py` 检查并与机器报告事实合并，形成受保护报告数据；不得由模型手填机器事实；
12. 从同一冻结评分真值和同一正式报告数据运行 `build_research_workbook.py`、`build_semantic_rules_workbook.py` 和 `build_docx_report.py`；不得修改旧 Office 单元格或旧报告数字；
13. 在严格只读的 `VALIDATE` 阶段运行 `validate_deliverables.py`，同时传入三份 Office、来源台账、原始/语义/正式证据台账、刷新后检索日志、机器维度审计、综合评分 JSON、报告数据 JSON、详细运行日志、正式 Skill 根目录、发布版完整性清单、受保护写入台账、真值冻结和预检；
14. 第一轮无效时按完整错误清单合并最上游根因，只允许一次集中修复和一次下游整链重建；第二轮仍无效立即以非收敛终态停止；
15. 人工抽查关键页面、原文—轨迹—分值链、发布协议版本与 SHA-256、词表缺口、复核队列、来源表、公式、图表、深层论证、反重复结果、字体、英文中文释义、结论和跨文件数字；
16. 生成并验证正式交付来源封印后，只把四份固定成果交给用户。

## 9. 重新打开与联合验收

`validate_deliverables.py` 不依赖本机 Excel 或 Word，而是重新打开三个 OOXML 包、解析 XML，并独立读取详细运行日志与发布版完整性清单。它检查：

- 两份 XLSX 和 DOCX 的 OOXML 完整性；
- 正式 Skill 发布版哈希在运行期间未发生变化；
- 三份 Office 与报告数据当前哈希均来自允许脚本在 `REPORT_BUILD` 阶段登记的受保护写入记录；
- 真值冻结清单中的来源、原始/语义/正式证据、检索、审计、协议、代码簿和评分哈希全部未改变；
- 全链预检为有效，运行状态、日志阶段与正式输入使用同一任务编号；
- 采集清单、内容快照、canonical 台账、纠错事件、当前有效视图、定位审计、碰撞审计和准入提交可独立复验；每条正式原文或原生数值均能落回来源快照；
- `report_truth.json` 可由冻结工件重编译，叙事未越权包含机器事实，报告数据同时绑定机器真值、叙事和自身哈希；
- 原始证据 ID、语义证据 ID 和正式证据 ID 构成合法子集链，且所有文件只含同一任务运行编号；
- 机器维度审计与精确来源、检索、正式证据摘要绑定，评分输入封印可复核；
- 详细运行日志的事件顺序、真实时间、页面数、三层证据数、审计状态、评分状态和终态摘要与其他文件一致；
- 主 XLSX 的七个工作表名称和顺序；
- 每表关键表头；
- 样本明细中的原生数值与语义量化字段、阈值、复核状态、轨迹和平台内权重；
- 表头字体、字号、颜色、填充、对齐、换行和行高；
- 来源页面 ID 与 CSV 完全一致；
- 页面数不少于 150；
- 检索日志非空；
- 公式数和七维图表；
- DOCX 封面、目录、两个分页符、研究口径和十五个编号一级标题；
- 全文二级标题顺序、七维标题及每维三个三级标题；
- 每维正文最低深度、八个结构化叙事字段和二十九项逐维标签；
- 每个维度至少一个可点击的代表性来源；
- 报告正文及结论中文字符数、完全重复与近重复、证据—机制—反证—边界—判断链、限定字体、英文中文释义、有效样本目标与实际数、深度迭代状态和样本边界声明；
- 研究口径、方法、总体评价、七维分析和限制中对语义量化、否定、转折、置信度、证据可靠性与复核的披露；
- 主 XLSX 中逐维证据数、来源页、来源类型、定向轮次和审计状态，以及从重开文件独立复算的强穷尽条件；
- 从底层正式评分证据独立重建候选、实际计分、计分方向、平台最低样本状态、平台倾向、跨平台七维分、转换分、固定权重加权分和综合分，并逐项比对评分 JSON、报告数据 JSON、DOCX 与 XLSX；
- 证据充分但得分为空、计分不足但存在分数、正中负数量与实际计分数不相等、平台或跨平台结果无法复算、缺失图表点被画成 0 均为硬失败；
- 十二张分析表的表头与顺序；
- 全部来源 URL 是否进入 DOCX，来源行数是否与台账一致；
- 十九字段机器行；
- URL 是否泄露敏感查询参数。
- 规则 XLSX 的固定文件名、七表精确顺序与表头、表头样式、评价协议版本、代码簿版本与 SHA-256、任务期无规则变更、至少三个发布校准来源与两个域名、发布校准决策、双语极性词表、双语七维词表、机器可读近义释义、上下文规则和八项编码解析规则。
- 正式 validation 不超过两轮，最终错误数为零；验收后无上游哈希变化，不存在非收敛或不可信写入终态；
- 正式交付来源封印中的任务、发布、冻结、证据、检索、审计、评分、三份 Office、日志、validation 与错误清单哈希全部可复核。

验证通过只说明文件结构和内部一致性通过，不替代对网页真实性、引用支持程度和研究判断的人工复核。

## 10. 跨平台依赖处理

生成 XLSX 需要 Python 3 和 `xlsxwriter`。生成 DOCX 需要 Python 3 和 `python-docx`。验收脚本只使用 Python 标准库，可在没有 Office 的环境中运行。

若当前平台已经提供等价的原生 Office 生成工具，可以使用，但最终文件必须满足主 XLSX 七表、规则 XLSX 固定七表、DOCX 标题结构、详细运行日志和四份成果联合验收规则。不要把平台专有 SDK、绝对路径、盘符或登录状态写入 Skill。

若缺少依赖且平台允许安装，按当前平台的包管理机制安装。若平台不允许安装但能用其他库创建等价文件，保持字段、样式和结构一致。若无法生成真实 DOCX、两份 XLSX 和实时详细运行日志，不得宣布正式完成。
